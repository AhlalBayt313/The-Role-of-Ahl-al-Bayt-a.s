# v228 — এরর লগ + গোপনীয়তা-বান্ধব ব্যবহার-পরিসংখ্যান (নতুন ফাইল: error-log.js, diagnostics.js)

## কেন
ব্যবহারকারীর ফোনে কিছু ভাঙলে জানার উপায় ছিল না (`window.onerror` / `unhandledrejection` ছিল না), আর কোন ফিচার ব্যবহার হয় বা কোন পেজে মানুষ অ্যাপ ছাড়ে তারও হিসাব ছিল না। এখন দুটোই আছে — **সব কিছু শুধু ডিভাইসে, কোনো সার্ভার/অ্যাকাউন্ট/কুকি/বাইরের স্ক্রিপ্ট ছাড়া।**

## কী বদলেছে
| ফাইল | বদল |
|---|---|
| `assets/js/core/error-log.js` | **নতুন।** `<head>`-এ সবার আগে লোড হয়। JS error, unhandled promise rejection ও ব্যর্থ `<script>/<link>/<img>` লোড ধরে। |
| `assets/js/core/diagnostics.js` | **নতুন।** ব্যবহার-গণনা + `?page=diagnostics` পেজ + ব্যাকআপের সাহায্যকারী ফাংশন। `browser-history.js`-এর **আগে** লোড হয় (render() wrap করে)। |
| `index.html` | দুটি `<script>` ট্যাগ (একটি `<head>`-এ, একটি `browser-history.js`-এর ঠিক আগে) |
| `assets/js/core/data-backup.js` | নতুন ঐচ্ছিক গ্রুপ `diag` (ডিফল্টে বন্ধ), দুটি key, যাচাই/মার্জ নিয়ম, ডায়াগনস্টিক পেজের লিংক-ব্লক, রিস্টোরের আগে `dgFreeze()`, এক্সপোর্টের আগে `dgFlush()` |
| `assets/js/core/script-4-boot.js` | পেজ-ম্যাপে একটি লাইন (`diagnostics`) |
| `assets/js/core/script-1-core.js` | বাংলা ও ইংরেজি শিরোনাম (`diagnostics`) |
| `assets/css/style.css` | শেষে একটি `.dg-*` ব্লক (মুছে দিলে আগের অবস্থা) |
| `sw.js` | CACHE `ahlbayt-v228`, নতুন দুই ফাইল precache তালিকায় |

কোনো বিদ্যমান ফাংশন, id, state key বা localStorage key বদলায়নি। কোনো ধর্মীয় কনটেন্ট/JSON ছোঁয়া হয়নি।

## এরর লগ (`ahlbayt_errlog`)
- সর্বোচ্চ **৫০টি আলাদা সমস্যা**; একই সমস্যা আবার হলে নতুন এন্ট্রি নয়, কাউন্টার (`×n`) ও শেষ সময় বাড়ে।
- প্রতিটি এন্ট্রি: ধরন, বার্তা, ফাইল:লাইন, ছোট stack, পেজ, অ্যাপ ভার্সন (SW cache নাম থেকে), মোটামুটি পরিবেশ (`android · chrome 129 · PWA`), সংখ্যা, প্রথম/শেষ সময়।
- **গোপনীয়তা:** URL থেকে `?query/#hash` ও নিজের origin বাদ, লম্বা টোকেন-সদৃশ স্ট্রিং `…` হয়ে যায়, `< >` মুছে যায়, দৈর্ঘ্য সীমিত। ব্যবহারকারীর লেখা, স্টোরেজের ভেতরের তথ্য, IP বা কোনো আইডি নেয় না।
- বাদ: ব্রাউজার-এক্সটেনশনের error, নিরীহ `ResizeObserver loop` বার্তা।
- এক পেজ-লোডে সর্বোচ্চ ৪০টি ঘটনা প্রক্রিয়া হয় (লুপে হাজারবার error হলেও স্টোরেজ ভরে না)। বাইরের রিসোর্সের ব্যর্থতা (যেমন অফলাইনে মানচিত্রের টাইল) হোস্ট প্রতি **একটি** এন্ট্রি; রিসোর্স-এন্ট্রি সর্বোচ্চ ১৫টি, তাই আসল error কখনো ঠেলে বের হয় না।
- হাতে লগ করতে চাইলে: `try { … } catch (e) { __dgLog.report(e, 'নাম'); }`

## ব্যবহার-পরিসংখ্যান (`ahlbayt_usage`, শেষ ৯০ দিন, দিন-ভিত্তিক)
| অক্ষর | কী গোনা হয় |
|---|---|
| `s` | সেশন (পেজ লোড, অথবা ৩০+ মিনিট দূরে থাকার পর ফেরা) |
| `v` | পেজ ভিউ (পেজ বদলালে একবার) |
| `x` | **যে পেজ খোলা থাকতে অ্যাপ ব্যাকগ্রাউন্ডে গেছে/ট্যাব বন্ধ হয়েছে** (ছেড়ে যাওয়ার পেজ) |
| `w` | পেজে কাটানো সেকেন্ড (শুধু দৃশ্যমান সময়, প্রতি অবস্থান সর্বোচ্চ ৩০ মিনিট) |
| `e` | বাটন/ফিচারের নাম (`data-action`), `changePage` ছাড়া |
| `c` | কোন দোয়া/যিয়ারত/আমল/পোস্ট কতবার খোলা (আইডি দিয়ে, সেরা ২০০) |

**গোনা হয় না:** আপনার লেখা কিছু (সার্চের শব্দ, নোট, জার্নাল), লোকেশন, নাম, আইডি, IP, user-agent। বাটনের প্যারামিটার শুধু ওই চার "খোলা" অ্যাকশনের কনটেন্ট-আইডি হিসেবে রাখা হয়।
- পেজে "গণনা বন্ধ করুন" সুইচ আছে (`ahlbayt_usage_off`); "পরিসংখ্যান মুছুন" বাটনও আছে।
- গণনা মেমোরিতে ছোট delta হিসেবে জমে ~১৫ সেকেন্ড পরপর / ব্যাকগ্রাউন্ডে যাওয়ার সময় / `pagehide`-এ স্টোরেজে মার্জ হয়। দুই ট্যাবে খুললেও একে অপরকে overwrite করে না।
- ফোনের ফুল স্টোরেজ বা quota ভরলে সবচেয়ে পুরোনো দিন বাদ যায়; সর্বোচ্চ ~২৫০ KB।

## ডায়াগনস্টিক পেজ (`?page=diagnostics`)
- **এরর লগ:** তালিকা (বিস্তারিত stack খোলা/বন্ধ), **রিপোর্ট কপি** (সমস্যা জানানোর জন্য), **ফাইল ডাউনলোড** (JSON), লগ মুছুন।
- **পরিসংখ্যান:** ৭/৩০/৯০ দিন; সেশন, পেজ ভিউ, সক্রিয় দিন, গড় সময়/সেশন; সবচেয়ে বেশি দেখা পেজ (গড় সময়সহ); ছেড়ে যাওয়ার পেজ (শতাংশসহ); বেশি ব্যবহৃত বাটন; সবচেয়ে বেশি খোলা কনটেন্ট।
- পৌঁছানো: **ডেটা ব্যাকআপ** পেজের নিচের "ডায়াগনস্টিক" ব্লক থেকে, অথবা সরাসরি `?page=diagnostics`। মেনুতে আলাদা আইটেম যোগ করা হয়নি।
- পেজটি সবার জন্য খোলা (যে যার নিজের ডিভাইসের তথ্য দেখে); আগের অ্যাডমিন-অনলি "পরিসংখ্যান" পেজ (`analytics`, মোট পেজ ভিউ) অপরিবর্তিত।

## ব্যাকআপে এক্সপোর্ট
- নতুন গ্রুপ **ডায়াগনস্টিক** (ডিফল্টে **বন্ধ**; কারণ এটি ব্যবহারকারীর ডেটা নয়, ডিভাইসের তথ্য)। ব্যাকআপ ফাইলের `format` একই (১) — পুরোনো ভার্সন অচেনা key বাদ দেয়।
- রিস্টোরে প্রতিটি মান আবার normalize/পরিষ্কার হয় (`<>` মুছে, দৈর্ঘ্য/সংখ্যা/key সীমা, `__proto__` ইত্যাদি বাদ)। মার্জে প্রতিটি কাউন্টারের **max()** নেওয়া হয়, তাই একই ফাইল দুবার রিস্টোর করলে সংখ্যা দ্বিগুণ হয় না।
- রিস্টোরের ঠিক আগে `dgFreeze()` চলে, তাই চলতি পেজের মেমোরির গণনা রিস্টোর-করা মানের ওপর লেখা হয় না।

## সীমা (জেনে রাখা ভালো)
- **এটি শুধু ওই ডিভাইসের ব্যবহার দেখায়।** অন্য দর্শকরা কতজন, কোন পেজ জনপ্রিয় — এটা জানতে হলে সার্ভার-সাইড কিছু লাগে (যেমন GoatCounter/Umami/Plausible)। সেটা তৃতীয় পক্ষের স্ক্রিপ্ট, আপনার অ্যাকাউন্ট ও গোপনীয়তা-নীতির সিদ্ধান্ত — তাই এখানে যোগ করা হয়নি।
- **ধরা পড়ে না:** যে error অ্যাপের নিজের `try/catch` গিলে ফেলে; Service Worker-এর ভেতরের error; পেজ ক্র্যাশ/OS কিল।
- ডেটা ব্রাউজার ডেটা মুছলে হারায় (ব্যাকআপের ডায়াগনস্টিক গ্রুপে নিয়ে রাখা যায়)।
- "ছেড়ে যাওয়া" মানে অ্যাপ ব্যাকগ্রাউন্ডে যাওয়া — স্থায়ী প্রস্থান নয়; ট্যাব বদলালেও একবার গোনা হয়।

- **বাকি (ফোনে):** Android/iOS-এ বাস্তব ব্যবহারে `pagehide`/ব্যাকগ্রাউন্ডে flush কাজ করছে কিনা, আর "রিপোর্ট কপি" (clipboard) iOS PWA-তে। PWA আপডেটের পর (v228) পরীক্ষা করুন।
